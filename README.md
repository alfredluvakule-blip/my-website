# Perfusio — Cardiopulmonary Bypass Perfusion Recording System

Production-oriented, hospital-grade web application for recording, monitoring, and
managing **Cardiopulmonary Bypass (CPB) perfusion data** during cardiac surgery.
Built for perfusionists to use live in the operating room, with clinical
calculations, automatic alerts, an auto-generated bypass timeline, role-based
access, audit logging, and anonymized research export.

> ⚕️ **Clinical safety note.** This software is decision-support and record-keeping
> tooling. Every derived value and alert is guidance; the ACT, the pump, and
> institutional protocol always govern actual clinical action. Validate against
> your own protocols before any real-world use.

---

## Architecture

A **modular monolith** in an npm-workspaces monorepo. The Express API is the only
writer of clinical data; the browser reads live data via Supabase Realtime, with
Postgres RLS holding that line as defense in depth.

```
Next.js 15 (App Router, PWA)  ──REST──▶  Express API (TypeScript)  ──▶  Supabase
        │                                     │                          Postgres (RLS)
        └────────── Realtime (read-only) ─────┴──────────────────────▶   Auth · Storage
```

### Monorepo layout

```
perfusio/
├── packages/
│   ├── clinical/     # Pure, unit-tested clinical formulas. No I/O. Must never be wrong.
│   └── contracts/    # Zod schemas + types shared by web forms and API validation.
├── apps/
│   ├── api/          # Express + Prisma. Sole writer of clinical data.
│   │   ├── prisma/   # schema.prisma + seed
│   │   └── src/
│   │       ├── platform/   # config, logger, db, audit, encryption, errors
│   │       ├── http/       # middleware, pagination, openapi, app assembly
│   │       └── modules/    # identity, patients, cases, perfusion, alerts,
│   │                       # equipment, analytics, research, reports
│   └── web/          # Next.js 15, React 19, Tailwind, TanStack Query, Zustand, Recharts
├── supabase/migrations/   # session context, RLS policies, realtime publication
├── nginx/                 # reverse proxy
└── .github/workflows/     # CI
```

Two packages are singled out because they are **correctness-critical and shared**:

- **`@perfusio/clinical`** — every formula (BSA, BMI, pump flow, cardiac index,
  DO₂/DO₂i, hemodilution, heparin/protamine, fluid balance, CPB/cross-clamp
  timing). Pure functions, 100% unit-tested. If EF-style logic lived in three
  places it would disagree in three places; here it lives once.
- **`@perfusio/contracts`** — one Zod schema per domain object, imported by the
  Next.js forms (validation + typing) **and** the Express API (request
  validation). This is what stops the form and the table drifting apart.

**Derived values are never trusted from the client.** BSA/BMI, DO₂i, cardiac
index, and CPB/cross-clamp durations are recomputed server-side by
`@perfusio/clinical` and persisted, so a stale or spoofed number can't be stored.

## Getting started

### Prerequisites
- Node.js 20+
- A Postgres database (local Docker, or a Supabase project)

### 1. Install
```bash
npm install
```

### 2. Configure environment
```bash
cp .env.example .env
# Fill in DATABASE_URL / DIRECT_URL and the Supabase keys.
# apps/web reads NEXT_PUBLIC_* — put those in apps/web/.env.local
```

### 3. Build shared packages & set up the database
```bash
npm run build --workspace @perfusio/clinical
npm run build --workspace @perfusio/contracts
npm run db:generate            # prisma generate
npm run db:migrate             # prisma migrate dev
npm run db:seed                # demo hospital, users, patient, case
```

Then apply the Supabase-specific SQL (RLS, realtime) from `supabase/migrations/`
in order — via the Supabase SQL editor or `supabase db push`.

### 4. Run
```bash
npm run dev        # API on :4000, web on :3000
```

- Web app: http://localhost:3000
- API docs (Swagger): http://localhost:4000/api/v1/docs
- OpenAPI JSON: http://localhost:4000/api/v1/openapi.json

### Or run the whole stack in Docker
```bash
docker compose up --build
# App via Nginx: http://localhost:8080
```

## Testing & quality

```bash
npm run test        # clinical + API unit tests (Vitest)
npm run typecheck   # strict TypeScript across all workspaces
```

- **`@perfusio/clinical`** has full unit coverage — the formulas are the part
  that must never be wrong.
- **RBAC** and **alert rules** are unit-tested from their truth tables.
- **Research anonymization** is tested to prove identifiers are stripped.

CI (`.github/workflows/ci.yml`) installs, builds packages, generates Prisma,
typechecks every workspace, runs unit tests, and builds the web app on every PR.

## Feature map

- **Roles & auth** — 10 roles (Administrator → Guest), each with a distinct
  permission set enforced server-side (`modules/identity/permissions.ts`);
  Supabase Auth for login, email verification, and password reset.
- **Dashboard** — today's / running / completed / cancelled cases, mean CPB,
  cross-clamp, ACT, temperature and flow, and pump cases by month.
- **Patient registration** — with live, server-authoritative BSA & BMI.
- **Clinical calculators** — BSA, BMI, prime volume, target flow, cardiac index,
  DO₂/DO₂i, hemodilution (predicted Hct/Hb), heparin & protamine dosing,
  CPB/cross-clamp timing — all from `@perfusio/clinical`.
- **Intraoperative monitoring** — periodic records (configurable 1/3/5/10/15 min
  or manual), full hemodynamics + ABG, live DO₂i/CI derivation, trend charts.
- **Automatic alerts** — low ACT, low flow, low reservoir, high line pressures,
  temperature bounds, low hematocrit, high lactate, critical potassium, low DO₂i,
  expired equipment.
- **Auto timeline** — canonical bypass events; CPB and cross-clamp durations are
  recomputed from the events themselves.
- **Equipment library** — categories, lot/expiry tracking with expiry flagging.
- **Research export** — anonymized, completed-case datasets (CSV/JSON) with
  pseudonymous subject ids and banded ages.
- **Security** — hospital-tenant isolation, RBAC, RLS, field-level AES-256-GCM
  encryption for PHI, soft-delete everywhere, append-only audit trail.
- **UX** — clinical blue/white theme, dark mode, OR touchscreen mode, PWA
  manifest, responsive tables and charts.
